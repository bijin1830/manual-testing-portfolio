A practical portfolio showcasing my **manual software testing approach** through synthetic examples of test planning, test design, functional testing, regression testing, defect reporting, RTM and UAT validation.

This repository reflects my strongest QA experience: understanding requirements, preparing test coverage, executing scenarios, reproducing issues, validating fixes and communicating defects clearly.

> **Privacy note:** All requirements, test data, screenshots/examples and defect details in this repository are synthetic. No employer, client, bank, merchant, production or confidential information is included.

## What this portfolio demonstrates

- Requirement analysis and testability review
- Test planning and scope definition
- Functional, regression, smoke and sanity testing
- Positive, negative and boundary-value testing
- End-to-end scenario validation
- Test case preparation and execution thinking
- Requirement Traceability Matrix (RTM)
- Defect reporting with severity and priority
- Retesting and regression after fixes
- UAT readiness checks
- Basic API/database validation awareness
- Clear QA documentation

## Demo application used for examples

The documentation assumes a fictional **Customer Commerce Portal** with the following modules:

- Login and account access
- Product search and cart
- Checkout
- Payment selection
- Order confirmation
- Order history
- Refund request

The application is fictional and is used only to demonstrate manual QA practices.

## Example coverage

| Module | Example manual checks |
|---|---|
| Login | Valid/invalid credentials, blank fields, lockout, session handling |
| Search | Exact/partial search, no-result behavior, special characters |
| Cart | Add/remove items, quantity limits, totals and persistence |
| Checkout | Mandatory fields, address validation, navigation and totals |
| Payment | Payment selection, success/decline/cancel/timeout behavior |
| Orders | Confirmation, reference generation, order-history visibility |
| Refund | Eligible/ineligible order, amount validation, status updates |
| Regression | Critical path validation after fixes and release changes |

## Test design techniques represented

- Risk-based regression selection

## Defect reporting approach

A useful defect should allow another person to reproduce the issue without guessing. My sample reports include:

- Clear title
- Environment/build
- Preconditions
- Reproduction steps
- Expected result
- Actual result
- Severity and priority
- Evidence/reference details
- Retest result
